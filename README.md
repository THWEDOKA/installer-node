# Remnawave Node Installer

Установщик ноды Remnawave с автоматическим созданием профиля Xray, ноды, хоста и привязкой inbound к Internal Squad через API панели.

**Язык:** [Русский](README.md) · [English](docs/README_EN.md)

## Что будет создано

Установщик разворачивает Remnawave Node, Nginx на сокете REALITY и один выбранный веб-сервис как сайт прикрытия. Выпускает сертификат Let’s Encrypt для этого сайта, запускает Cloudflare WARP в режиме локального SOCKS5 и отправляет [профиль Xray](profile.json) в панель. TAG и ключ REALITY создаются заново; `serverNames` и SNI получают указанный домен. Хост создаётся на порту 443, а inbound добавляется в выбранную Internal Squad.

Маршруты профиля соответствуют предоставленному шаблону. Для правила блокировки используется существующий outbound `BLOCK`; повторяющийся `beeline.ru` удалён. Трафик `.ru`, `.su`, `.рф` и `geosite:google` направляется через WARP. Остальной трафик идёт через `DIRECT` по умолчанию.

## Требования

- Чистый сервер Ubuntu 22.04+ или Debian 12+ с root-доступом и `apt`.
- Установленная и доступная по HTTPS панель Remnawave с API-токеном, который может создавать профиль, ноду, хост и изменять Internal Squad.
- Домен ноды с A/AAAA-записью на этот сервер. TCP/80 должен быть доступен извне при первичном выпуске сертификата; TCP/443 — клиентам.
- Порт TCP/2222 должен быть доступен **только с IP панели**. Ограничьте его в firewall провайдера или на сервере до запуска. Установщик не меняет правила firewall и не предполагает, что SSH работает на порту 22.
- Свободные порты TCP/443 и TCP/80 при выпуске сертификата, а также TCP/8080 на loopback.

## Установка

```bash
git clone https://github.com/x1roko/node-setup.git
cd node-setup
sudo ./install.sh
```

В начале выберите `Русский` или `English`. Затем введите адрес панели, API-токен, домен ноды, email сертификата, имя ноды, код страны, веб-сервис, адрес ноды для панели и Internal Squad. Токен вводится скрыто и не сохраняется. Повторный запуск для того же домена продолжает работу по файлу состояния, расположение которого приведено ниже.

Если сертификат уже есть в `/etc/letsencrypt/live/<домен>/`, установщик использует его. Иначе Certbot выполняет HTTP-01 на TCP/80. При продлении сертификата deploy hook обновляет копии для Nginx и перезапускает прокси.

## После установки

```bash
sudo docker compose -f /opt/remnanode/docker-compose.yml ps
sudo docker compose -f /opt/remnanode/nginx/docker-compose.yml logs --tail=100
sudo curl --proxy socks5h://127.0.0.1:40000 https://www.cloudflare.com/cdn-cgi/trace
```

Если система установила `docker-compose` вместо плагина Compose, замените `docker compose` в командах проверки на `docker-compose`.

Проверьте в панели статус ноды, профиль, хост и состав выбранной Internal Squad. Проверьте, что панель может подключиться к адресу ноды на TCP/2222. Настройки маршрутизации действуют **на сервере**, а не меняют клиентские правила.

## Файлы и порты

| Путь / порт | Назначение |
| --- | --- |
| `/opt/remnanode/installer-state.json` | UUID созданных объектов и ключ ноды; права `600` |
| `/opt/remnanode/node.env` | Секрет ноды; права `600` |
| `/opt/remnanode/nginx/` | Конфигурация Nginx и копии сертификата |
| `/opt/remnanode/service/` | Compose-файл выбранного веб-сервиса |
| `443/tcp` | VLESS REALITY |
| `2222/tcp` | API Remnawave Node, только для панели |
| `40000/tcp` | локальный SOCKS5 WARP |
| `8080/tcp` | веб-сервис на `127.0.0.1` |

## Восстановление и ограничения

При ошибке исправьте причину и запустите `sudo ./install.sh` снова с теми же параметрами. Файл состояния содержит секрет ноды; храните его как приватный. Установщик не обновляет уже созданные объекты панели при изменении домена или сервиса: для изменений используйте панель и соответствующие Compose-файлы. Сетевые политики, DNS и работа внешней панели остаются за администратором. Наличие geosite-категорий зависит от данных Xray в образе ноды.

API и схема установки сверены с [документацией Remnawave](https://docs.rw/install/remnawave-node/), [Config Profiles](https://docs.rw/learn-en/config-profiles/), [Hosts](https://docs.rw/learn-en/hosts/) и [Internal Squads](https://docs.rw/learn-en/squads/).
